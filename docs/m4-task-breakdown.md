**引擎侧口径**：F7 不新造公式——它是「把不同的输入喂给同一个 `project`」，然后展示差值。任何新纯函数都放 `packages/core`、带单测，遵守 barrel 合并纪律（`index.ts` 不并发编辑）。

## 1. 内容与口径规则

1. **不编数据**：情景的默认幅度（如涨薪 10% / 副业 +$500/月 / 大额支出 $20,000）要么来自用户自己的输入，要么标为「示例」且可改，**不得当成对用户的预测**。
2. **三状态仍是一等状态**（PRD §6.3）：失业情景大概率落到 `no-net-savings`，这**不是错误分支**，要有独立文案。
3. **报告里每个数字都要能追到假设**：报告是「假设 + 算术」的快照，不是结论。假设清单与免责声明沿用 M1 纪律，且必须 **SSR / 静态可见**（不被 JS 关掉）。
4. **措辞红线照旧**（`copy-guard.test.ts`）：不出现「稳赚 / 躺赚 / 保证收益 / 预期收益 / 你也能拥有 / 你将拥有」；情景推演只陈述算术与状态，不得读成投资或职业建议。
5. **双语**：M4 的新界面文案必须**同时**进 `lib/messages.ts` 的 zh 与 en（`en` 用类型强制覆盖每个 key），不能只写中文。

## 3. 每片的验收通用项

1. `npm test` 与 `npm run check` 绿；core 改动走 barrel 合并纪律。
2. 新文案过 `copy-guard.test.ts`：禁语清单、数字与来源一致；情景与报告的措辞不得构成投资 / 职业建议。
3. 免责与假设：报告与情景页带假设清单 + 免责声明，**SSR / 静态可见**。
4. 移动端 390×844 无溢出；键盘可达；`prefers-reduced-motion` 生效。
5. 双语：新增文案 zh + en 两份齐全（`messages.ts` 的类型闸门会钉住）。
6. 冒烟脚本保持全绿；若涉及生产动作（支付、报告服务端），按 M2 的教训**看到真实 200 + 数据落地才算数**。

## 4. 明确不做（M4 边界）

- 账号体系（`m2-decisions.md` D4，仍押后，判据依赖回访读数）。
- 多剧本 / 多身份存档（F9，P2）、匿名社区（F10，P2）。
- 六通道其余通道、人生快进剧情、随机黑天鹅（`simulation-gameplay.md` §2.3 后置项）。
- 名人原型卡（等 `deferred-items.md` #5 法务复核）。
- 把报告做成投资建议或收益预测——红线，不做。

## 5. 与度量的关系

M4 直接产出漏斗的**付费段**：`report:generate` / `report:export` / 付费墙点击。但**它的价值判断被 §11.2 的第三数卡住**：

> 付费意愿现在**拿不到**——没有可测对象（F8 未做，付费墙与支付按 D5 押后）。

所以顺序上建议：**S1（F7）先做**——它纯前端、不被任何东西阻塞、且直接增强「会反复回来重算」的留存假设（PRD §11.4）；**S2–S4 等 G1–G4 拍板**，其中 S4 还额外等一个付费意愿信号。
