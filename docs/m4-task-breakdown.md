## 1. 内容与口径规则

1. **不编数据**：情景的默认幅度（如涨薪 10% / 副业 +$500/月 / 大额支出 $20,000）要么来自用户自己的输入，要么标为「示例」且可改，**不得当成对用户的预测**。
2. **三状态仍是一等状态**（PRD §6.3）：失业情景大概率落到 `no-net-savings`，这**不是错误分支**，要有独立文案。
3. **报告里每个数字都要能追到假设**：报告是「假设 + 算术」的快照，不是结论。假设清单与免责声明沿用 M1 纪律，且必须 **SSR / 静态可见**（不被 JS 关掉）。
4. **措辞红线照旧**（`copy-guard.test.ts`）：不出现「稳赚 / 躺赚 / 保证收益 / 预期收益 / 你也能拥有 / 你将拥有」；情景推演只陈述算术与状态，不得读成投资或职业建议。
5. **双语**：M4 的新界面文案必须**同时**进 `lib/messages.ts` 的 zh 与 en（`en` 用类型强制覆盖每个 key），不能只写中文。

### S1 任务分解（F7 多情景推演 · 可立即开工）

**为什么它不被阻塞**：F7 不需要后端、不需要改冻结契约、也不需要先定报告形态——它就是把**改过的 profile 再喂一遍**已有的纯函数 `computeResults(draft, catalog, locale)`（`apps/web/src/lib/results.ts`），然后展示差值。§0 的 G1–G4 都卡不到它。

**情景口径（建议默认值，原型后可回调）**

| 情景 | 怎么改 profile | 建议默认 |
|---|---|---|
| 涨薪 | `income × (1 + r)` | r = 10%，可改 |
| 副业 | `income + m` | m = 500 / 月，可改 |
| 失业 | `income = 0`，`expense` 不变 | 固定口径（不可调） |
| 大额支出 | `savings − c`（一次性） | c = 20,000，可改 |

- 幅度**全部可改**，默认值只作起点，**不得呈现为对用户的预测**（§1 规则 1）。
- 失业必然落 `no-net-savings`（收入 0）——按一等状态给独立文案，不是错误分支。
- 大额支出走「减 `savings`」而非「加 `expense`」：它是一次性支出、不是月度开支，**`Profile` 无需改**（G5 = 零契约改动）。

除币种切换器更新 `fx` 外，没有任何一行代码写过 `draft.assumptions`。

| 项 | 取值 | 理由 |
|---|---|---|
| 契约 | **零改动**（G5 同 S1） | `Draft.assumptions: Assumptions \| null` 本来就在契约里；改的是数值不是公式，所以 `assumptionsVersion` 不 bump——那是口径版本 |
| 可调字段 | 只有 `returnRate` / `withdrawalRate` | `inflation` 不参与任何换算（`scenarioAnnualCost` 的 M1 注记）。给一个不动任何数字的输入框等于骗人；免责声明第 4 条已把这件事告诉了用户 |
| 区间 | r `0–20%`，提取率 `1–20%` | 下限是算术：够用线 = 年成本 ÷ 提取率，0 会解出无穷本金；上限之上达标年限落到 0–1 年，再高的收益率只会让这一屏像承诺收益。**拒绝而不是夹紧**——静默把 25% 改成 20%，用户以为自己填的就是 25% |
| 挂载 | 结果页内岛，**不新增路由** | 与 S1 同一判据 |
| 跨岛重算 | `writeDraft` 之后派发同页事件 `rich-sim:draft-updated` | 结果区与情景面板是两个独立岛、各读一份 draft。不广播的话，改完假设只有清单跟着动、上面的数字不动——而那正是这一功能唯一要给用户看的东西。事件不是存储 key、不落盘，不在冻结清单内 |
| 埋点 | `assumptions:edit`（props 只有字段名）/ `assumptions:reset` | 用户自填的假设属于财务数据：**数值从头就不发**（收集端本来丢 props，但源头不发才算红线）。冒烟有一条断言盯「props 里出现数字就红」 |

**合规清单不能替不成立的假设背书**：清单是 SSR 渲染的（红线：不能被 JS 关掉），而 SSR 只可能印默认值。
所以 `[data-assumption]` 是留在**服务端 HTML** 上的钩子，岛在首帧与每次改动后把那几个节点改成真正在用的那套
（`lib/assumptions.ts` 的 `patchAssumptionDisplay`，`document` 注入以便单测）。关 JS 时那一屏仍是完整的
清单 + 免责声明，只是回到默认假设——那也是它实际会用的口径。设计器页恢复 draft 时同样同步一次
（`DesignerShell`），否则两个页面会各印一套数字。

**本片没做（不是漏了，是边界）**：`AssumptionsPanel` 的汇率行仍是 SSR 印的静态快照，切币种后不改写
（本片之前就是这样）；本金口径的换算条展开（`comparison-converter.md` §2.2 + `converter:expand`）
现在**前置条件已满足**（两个率真的可动了），仍未做。

**验收**：冒烟步骤 3.6 共 12 条——SSR 源码无岛 / SSR 仍印提取率与免责声明 / 提取率减半够用线翻倍 /
**情景面板（另一个岛）**基线年限跟着变长 / 清单同步成 2% / 刷新后仍是 2% / 越界报出允许区间且不改测算
不落盘 / 失焦拉回生效值 / 一键回默认且按钮随之消失 / 两个事件入队 / 事件不带数值。
本地实测见**本文开头的「当前读数」那一行**（全文只在那一处写总数；S1.5 收尾时是 212 / 92 / 86，已被后续切片叠掉）。

## 8. S1.6 · 本机测算历史与复盘（2026-10-08，F6 无账号的那一半）

发起人点的单子是「④a F6 local progress tracking」，口头批准的闸门是**给 `Draft` 加一个可选 history 字段**。
做完之后回头看，这一片真正的形状是：**把 §3.2 的批评变成设计约束**。

`product-concept.md` §3.2：「用『进度追踪 / 每月提醒』救留存是给健身 App 套的通用件：净资产按月几乎不动，
『进度』看不见，反而劝退。」这句话对本片是**成立**的，所以：

| 不做 | 做 |
|---|---|
| 目标完成度百分比（月尺度上小数点后才有动） | 两次测算之间的**差值**：年限动了几个、状态跨没跨档 |
| 「你进步了 / 继续保持」这类评价 | 只陈述差值；「与上次一致」也照常说出来 |
| 提醒 / push（要账号与后端，且 §3.2 已否定这条路） | 回访时自然看见，不主动打扰 |

| 项 | 取值 | 理由 |
|---|---|---|
| 契约 | `Draft` 增**可选** `history?: Snapshot[]`，`schemaVersion` 不动 | 口头批准的形态。可选 ⇒ 旧草稿天然兼容（缺字段 = 没有历史） |
| 写入口径 | **一个历日一条**，当天覆盖 | 按 keystroke 记会把「调了一下提取率」记成六条历史；按天记才对应「回访」这个单位 |
| 记什么 | 记**算出来的数**（年限 / 三状态 / 年成本 / 够用线）+ 当时净资产与币种 | 快照要回答「上一次这一屏说了什么」。用今天的引擎重算昨天的 profile，等于替昨天说一套它当时并不成立的数 |
| `writeDraft` | 不传 `history` 就**隐式保留** | 每个写方都是重建整个 `Draft` 字面量；逐条透传漏一处就静默抹掉用户历史。已写进 `CONVENTIONS.md` 的例外纪律 |
| 跨币种 | 金额**不放在一起比**，年限比 | 净值差跨单位没有意义；年限对币种是齐次的（本金 / 年储蓄 / 目标本金同乘一个因子），这条用 USD 与 CNY 两份 profile 各跑一遍引擎**差分验证**过，不是嘴上说 |
| 埋点 | `progress:view`，**零 props** | 快照本身不出本机（红线）。这个事件的存在就是读数：「这台机器今天回来看过，而且手里有至少两个历日的记录」 |
| 挂载 | 结果页内、`ResultsView` 同一块岛 | 复盘说的就是上面那些数，另开一个岛就得把同一套测算再算一遍，两处口径迟早分叉 |

**重入与写放大**：`writeDraft` 现在会广播同页事件，而本页正是监听方——落快照的写会把自己叫回来重算。
两条停止条件都写死在代码里：① `tracked` 在报点之后、写盘之前落下，重入只重渲染不再报点；
② `upsertToday` 值没变时返回**同一个数组身份**，调用方据此一个字节都不写。
冒烟里「同一天反复测算不增长（count=1）」这条钉的就是它——没有它，这一片最自然的失败方式是每次刷新都追加一条。

**对度量的意义（有限，别说大）**：PRD §11.2 的死结是 7 日回访率**算不出**（收集端不存标识符）。
`progress:view` 不改变这一点——它给不出分母，因此**不是回访率**。它给的是一个此前完全没有的计数：
「隔天再算并且看见了对照」发生了多少次。要看回访率仍需 CF Web Analytics 近似或改 D4 判据。

**验收**：冒烟步骤 3.7，15 条——SSR 源码无复盘块 / 首次测算只落一条 / 没有上一条时不编造对比 /
同一天反复测算不增长 / 上一条年限更大时报「提前 5 年」/ 同币种报净资产差 / 日期与间隔 / 合规措辞在块内 /
跨币种不给金额差 / 跨币种明说不比但年限仍比 / 状态跨档复用三状态词典 / `progress:view` 入队 /
该事件一个 props 都不带 / 英文态不夹中文。总数见**本文开头的「当前读数」**那一行（S1.6 收尾时是 238 / 107 / 101）。

**本片明确没做**：跨设备与账号（F6 的另一半，等 D4）；历史列表 UI（只有上一条 vs 这一条）；
把 `annualCost` / `enoughLine` 的差展示出来（已落盘，读数只挑了年限 / 状态 / 净资产三项，够回答「和上次比」）；
提醒、通知、进度条。
