## 1. 一句话

**先体验一次富豪人生，再看清你自己的路。**

用「幻想」吸引用户进来，用「你自己的真实收入」让他算清：想要的生活需要多少钱、现在差多远、要多久。

---

## 2. 背景与机会

### 2.1 问题

人们普遍对财富有两处认知断层：

1. **不知道富人生活的真实成本**——只看到消费，看不到维护、税费、风险与现金流压力。
2. **不知道自己的"够用线"在哪**——说不清"到底需要多少钱才够"，也无法把模糊的愿望变成可执行的阶段目标。

### 2.2 竞品空白

| 类型 | 代表 | 缺口 |
|---|---|---|
| 财富模拟游戏 | 各类"富人模拟"小游戏 | 纯娱乐，数字是假的，与用户真实财务无关 |
| 记账 / 理财工具 | 记账 App、理财计算器 | 数据很全，但没有体验、没有目标感、没有动力 |

本产品把两者缝在一起：**用模拟体验做钩子，用真实对标与目标规划做落点。**

### 2.3 为什么是现在

`待定`：需要补充市场时机论证（如：年轻人财务焦虑上升、FIRE 话题流行等）。当前不编造数据。

## 3. 目标与非目标

### 3.1 目标（Goals）

- G1：让用户在"设计/体验理想生活"的过程中，建立起"多少钱才够"的量化认知。
- G2：用用户真实收入做对标，产出**可执行**的阶段目标。
- G3：验证商业模式（见 §10）——先跑通"用完 → 回来 → 付费"的闭环。

### 3.2 非目标（Non-Goals）——明确不做

- **不做投资建议、不荐股、不推荐任何具体金融产品。** 只对用户自填假设做算术。
- **不做记账工具。** 不追求流水级数据录入，不替代记账 App。
- **不做社交 / 攀比社区。** MVP 阶段完全不做。
- **不做 3D 场景、不做多剧本堆量。** MVP 只做 1 个剧本。
- **不做 B 端。** 中长期再议。
- **不做原生 App。** 移动端由响应式 Web / PWA / 大陆微信小程序覆盖；原生 App 以付费+回访触发门驱动（见 [technical-design §10.1](./technical-design.md)）。

## 4. 目标用户

### 4.1 主要人群

22–40 岁、对财富好奇、愿意做长期规划、有稳定收入的年轻人（一线/新一线打工人、独立开发者、自由职业者）。

**排除**：想一夜暴富的人。他们不是用户——价值观不符，且会污染产品调性。

### 4.2 Persona

**A · 26 岁，一线城市互联网从业者**
月薪 2 万，存款 8 万，无房。想知道"5 年内买房"到底现实不现实，算不清首付、月供、储蓄速度之间的关系。

**B · 32 岁，二线城市，已婚有房贷**
家庭月收入 2.5 万，房贷每月 8000。在考虑要不要生二胎，想先量化它对家庭现金流和长期目标的影响。

两人的共同点：**问题都很具体、情绪很高、会反复回来重算。** 这是产品留存的基础（见 §11 风险）。

## 5. 核心价值主张

**先看见，再算清。**

- 看见：把"理想生活"和"富人生活"都摊开成可视化的成本结构。
- 算清：用你自己的数字，算出够用线、差距和年限。

一句话差异：**不是爽游，也不是记账本。**

## 6. 领域模型与核心算法

### 6.1 关键概念

| 概念 | 定义 |
|---|---|
| 生活场景 Life Scenario | 一组生活维度（居住、出行、家庭、教育、旅行…），每项对应年成本 |
| 理想生活年成本 | 场景内所有维度年成本之和 |
| 够用线 Enough Line | 支撑理想生活所需的资产/本金 |
| 现状 Profile | 用户的收入、支出、存款、负债 |
| 对标 Benchmark | 用户现状 vs 某个财富层级 |
| 阶梯目标 Milestone | 把大目标拆成的阶段目标 + 行动项 |

### 6.2 核心公式（示意，非最终模型）

- **理想生活年成本** = Σ 各维度年成本
- **够用线（需要多少本金）** = 理想生活年成本 ÷ 安全提取率
  - 安全提取率默认 4%，**必须显式展示为可调假设**，不能藏起来。
- **达成年限** = 用复利模型反解：`存款·(1+r)^n + 年储蓄·[((1+r)^n − 1)/r] ≥ 目标`
  - r 默认 4%，用户可调。
- **储蓄率** = 月储蓄 ÷ 月收入

> 所有结果必须附带假设清单与免责声明。模型只做静态推演，不做预测。

### 6.3 领域规则

- 所有输入均为用户自填，系统**不引入任何外部"建议"**。
- 结果永远展示"在什么假设下成立"，而非"将会如此"。
- 负储蓄（支出 ≥ 收入）与不可达（60 年内）必须作为**一等状态**处理，而非错误。

## 7. 用户旅程

### 7.1 主流程（核心闭环）

```
进入 → 设计理想生活 / 或先体验富豪剧本
     → 轻量录入真实财务（≤4 项）
     → 得到测算：够用线 · 差距 · 年限
     → 生成阶梯目标
     → 保存 → 回访 → 复盘
```

### 7.2 两条入口

- **钩子入口**：先玩富豪模拟剧本，产生"那我呢？"的好奇 → 转入测算。
- **直奔入口**：直接设计理想生活 → 测算。（对目标明确的用户）

两条入口最终汇入同一个测算闭环。

## 8. 功能需求

优先级：**P0 = MVP 必须**，P1 = 紧随其后，P2 = 更远。

### F1 · 理想生活设计器【P0】

用户用少量选择描述想要的生活，系统算出年成本。

- 维度（MVP 各给 3–5 个选项即可）：居住、出行、家庭与子女、旅行、保险与医疗、其他弹性。
- 输出：理想生活年成本 + 够用线。

**验收**：用户可在 3 分钟内完成；维度选择有合理默认值；年成本随选择实时更新。

### F2 · 轻量财务录入【P0】

- 字段：月收入、月支出、现有存款、负债。**不超过 4 项。**
- 精细模型（逐项支出）作为高级选项，默认收起。

**验收**：4 项以内；每项有示例值；可随时修改并重算。

### F3 · 测算引擎【P0】

- 输入：现状 Profile + 目标（够用线 或 目标净资产）。
- 输出：够用线、差距、按当前储蓄速度所需年限、储蓄率。
- 三种状态：**可达 / 不可达 / 无净储蓄**，均有清晰文案。
- 必须展示假设清单与免责声明。

**验收**：三种状态均有覆盖；结果区始终可见假设；修改任一输入即时重算。

### F4 · 阶梯目标【P0】

把大目标拆成阶段目标 + 行动项。

- 示例：提高储蓄率 → 攒出第一笔本金 → 抬升收入。
- 每阶段：目标值 + 一个具体行动项。

**验收**：至少 3 阶段；数值来自用户自身数据，而非通用模板；明确标注为示例路径。

### F5 · 富豪模拟体验【P0，最小版】

钩子功能。MVP 只做 **1 个身份剧本**。

- 内容：资产看板（房产/股权/基金/现金…）、每年持有成本、现金流波动。
- 目的：让用户产生"那我呢"的动机，并理解富人的**成本与风险**。
- 内容骨架（身份来源 / 生活维度 / 风格光谱 / 成本数字来源）：见 [富豪生活方式框架](./wealth-lifestyle-framework.md)。
- 玩法机制草案（购物交互 / 对比闭环 / 名人原型合规）：见 [模拟玩法设计](./simulation-gameplay.md)。

**验收**：资产可查看；持有成本可见；不含 3D；不做多剧本。

### F6 · 保存与复盘【P1】

- 保存方案、回访、目标进度追踪。
- **这是留存的关键**（见 §11），但依赖账号体系，放到 P1。

### F7 · 多情景推演【P1】

涨薪 / 副业 / 失业 / 大额支出对年限的影响。

### F8 · 深度报告导出【P1】

一次性生成的完整测算报告（对应可能的付费点，见 §10）。

### F9 · 多剧本 / 多身份存档【P2】

### F10 · 匿名社区【P2】

严格管控，禁止攀比炫富。优先级最低。

## 9. 非功能需求

- **合规**：所有测算页面强制展示免责声明；假设透明；绝不推荐具体产品。定位为**财商模拟教育工具**。
- **性能**：LCP < 2.5s，INP < 200ms，CLS < 0.1。
- **可访问性**：WCAG AA；键盘可达；对比度达标。
- **隐私**：MVP 不强制登录；若保存数据，须明确告知用途，不出售、不用于荐股。
- **兼容**：现代浏览器 + 移动端 Web；深色/浅色自适应。
- **语言**：中文优先。

## 10. 商业模式

> **尚未决策。** [构想文档 §5](./product-concept.md) 建议放弃订阅制、改为围绕"单个高赌注决策"的一次性付费，但发起人尚未拍板。

落地页当前展示了三档（免费 / 一次性深度报告 / 会员），**均为占位**。

需要决策的：
- 免费与付费的分界点在哪？
- 订阅 vs 一次性？
- 首个付费场景是哪一个（买房 vs 租 / 辞职 / 生娃 / 退休）？

**付费场景建议（2026-10-03 讨论，`待定`）**：首个付费场景推荐 **买房 vs 租**。理由：①与理想生活设计器「居住」维度天然衔接（最重的一维）；②与模拟购物车最大资产项（房产）衔接顺；③Persona A（26 岁一线从业者）的核心痛点正是它；④测算实现成本最低（首付 / 月供 / 储蓄速度，纯静态推演）。辞职 / 生娃 / 退休均后置。

## 11. 度量与成功标准

### 11.1 北极星指标

**完成「设计生活 → 得到测算」的会话数。**

### 11.2 MVP 验证三数（上线后最先看）

1. **完成率**：进入后走完测算的比例。
2. **7 日回访率**：一周后是否有人回来。
3. **付费意愿**：是否有人愿意为深度报告付哪怕 9.9 元。

### 11.3 目标阈值

`待定`。初始假设（需校准，非承诺）：完成率 ≥ 40%、7 日回访 ≥ 10%、付费意愿测试出现 ≥ 3% 转化。

### 11.4 关键风险

- **留存风险**：核心洞察（"原来要这么久/这么多"）可能是**一次性情绪**，撑不起复购。缓解：把产品重心放在"会反复回来重算"的具体决策上（§4.2 的 Persona A/B）。
- **漏斗风险**：爱玩模拟的人与愿付费的人可能是两拨人。缓解：双主线入口都要通向同一个测算闭环。
- **护城河风险**：测算是复利公式，易被复制。壁垒需落在内容（生活场景 → 成本的模型与数据）与体验上。`待验证`
