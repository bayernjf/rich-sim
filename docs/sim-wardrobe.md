# 拟物衣柜（Sim Wardrobe）设计 · v1 · 2026-10-10

> 状态：**S1 框架 + S2 衣物条目已实现（2026-10-10），仅剩 AI 衣物图待 `OPENAI_API_KEY`**。
> 在富豪商城内加「衣柜」：拟物衣橱里可视化挑衣服，选中件计入购物车年成本。
> 首批 5 件衣物（全定制西装 / 高定晚礼服 / 复杂功能腕表 / 稀有皮手袋 / 定制皮鞋）
> 已带公开来源上架，图片槽位缺失自动回退占位衣架，补图零代码改动（§5）。

## 1. 为什么做

商城卡片流是「电商列表」，衣服是其中最不适合列表化的品类——挑衣服
的爽感来自「打开衣柜、从挂杆上取下来」。拟物衣柜把这个体感补齐，
选中后走与商城完全相同的加购→账单→负担率链路（算术零新增）。

## 2. 两个前置（§5 的阻塞项）

1. **衣物条目**：~~金额必须先补公开来源再进池~~ ✅ **已解除（2026-10-10）**——首批 5 件
   通用品类（不绑品牌）全部带 http(s) 来源入池，零售价与年持有摊提口径写进各自 `note`；
2. **衣物图**：候选 AI 插画，需要 `OPENAI_API_KEY`；不用真实品牌。**仍阻塞**，缺失自动回退占位衣架。

框架设计因此做到：**衣物池为空时衣柜照常渲染（空态），衣物与图片后补时零代码改动即展示**。

### 2.1 年成本口径（S2）

衣物一次购入、持有多年，`annualCost` **不取零售价而取年持有口径**＝零售价按显式
标注的教学穿着/持有寿命（10–30 年）直线摊提、含日常保养；零售价、来源汇率
（GBP→USD 用 ECB Frankfurter 快照）与摊提算式逐条写进 `note`。这与产品主题
「财富的真实持有成本」一致——一件 $9,900 的全定制西装，年持有约 $990。

## 3. 架构

| 件 | 位置 | 说明 |
|---|---|---|
| 衣物内容 | `apps/web/src/lib/sim-wardrobe.ts`（新） | `WARDROBE_ITEMS` + `wardrobePool()`；与体验项同套路放 **web 侧**（不进 core catalog，不受每维 3–5 项契约约束）。入池闸门与购物池同一规则：`source` 必须是 http(s) |
| 图片槽位 | `apps/web/public/mall/wardrobe/{optionId}.webp`（新目录） | 按 optionId 约定命名；组件 `<img onError>` 回退到占位挂衣杆，**图不存在时零报错** |
| 衣柜 UI | `MallArea.tsx` 新 tab `wardrobe` | 拟物衣橱（木纹柜体 + 挂杆 + 衣架，纯 CSS）；选中件复用 `toggle` 加购，`kind: 'consumer'`、`resellable: true`（可二手变卖） |
| 算术 | 零改动 | 衣柜件在 MallArea 内并入 `allItems` 参与 `cartBurdenSummary` / 抽屉 / 环形图 / 一键成目标，但**不出现在**「全部 / 消费品」tab——只在衣柜里挑 |

**为什么衣柜件不进 `items` prop**：`items` = `shoppingPool()` 是卡片流
目录；衣柜是独立陈列形态。MallArea 内部合并 `items + wardrobeItems`
供账务查找，陈列层各走各的 tab，两套装潢互不污染。

## 4. 红线对照（逐条）

| 红线 | 本设计 |
|---|---|
| 数值必须有来源或显式标注 | 入池闸门与购物池同规则（无 http(s) 来源不进池）；当前衣物池为空，页面上没有任何无源数字 |
| 不用真实品牌 | 衣物条目只用通用品类名（西装 / 礼服 / 腕表…），图也不用品牌款 |
| 不做促销话术 | 衣柜只有「试穿/收起」与加购，copy-guard 促销禁语闸门照样扫 |
| 用户财务数据不上传 | 加购走 `sim:add`/`sim:remove` 既有埋点，零新增事件 |
| 两本账不混 | 走既有 cart 字段，无新账本 |

不做清单：虚拟人台/身材建模、穿搭推荐、品牌联名、衣物折旧曲线。
