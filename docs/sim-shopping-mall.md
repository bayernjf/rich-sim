# 富豪商城（Sim Mall）设计 · v1 · 2026-10-09

> 状态：**草案，待发起人过目**。把 `/app/sim` 的清单式购物区升级成「购物网站」形态：
> 商品卡片流 + 分类 tab + 购物车抽屉 + 「结算 = 账单日」的爽感反转。
> 算术层零改动（`shoppingPool` / `cart*` / `cartBurdenSummary` 全部现成），这是纯体验切片。

## 1. 为什么做

现有购物区是文字清单：功能全（幂等加购、账单预览、负担率联动、一键成目标），但形态不像"购物"。
购物是六通道里「操作」通道的主体验，爽感（逛、挑、加车）越像真的电商，账单日的反转越疼——
这是产品「爽 1.5 秒，然后被账单反驳」内核的直接延伸。

## 2. 形态（一屏三态）

```
┌─ 分类 tab：[全部] [资产] [消费品] [体验]          🛒 购物车 (2) ─┐
│  ┌─────┐ ┌─────┐ ┌─────┐                                        │
│  │卡片区│ │卡片区│ │卡片区│  ← 商品卡：图标/插画 + 名称 + 年成本大字 + [加入购物车]
│  └─────┘ └─────┘ └─────┘                                        │
│  …（卡片流，按年成本降序）                                        │
└─────────────────────────────────────────────────────────────────┘
        点 🛒 → 右侧抽屉滑出：
        ┌──────────────────────┐
        │ 已购清单（可移除）      │
        │ ────────────────     │
        │ 下一期账单预览         │
        │ 基线 + 加购 = 合计    │ ← 负担率色块实时变色（绿/黄/红）
        │ [结算 · 翻到账单日]   │ ← 不是付款，是"看看你一年要付多少"
        │ [把这车生活设为目标]  │ ← 现有 adoptCartAsGoal，保留
        └──────────────────────┘
```

- **结算 ≠ 付款**：点「结算」滚动到账单日区块并短暂高亮——爽感到此反转为痛感。
  没有支付页、没有价格「优惠」话术、没有倒计时——那些是电商促成转化的伎俩，
  本产品是财商教育，方向相反。
- **抽屉即现有预览**：`cartBurdenSummary` 的输出原样搬进抽屉，一处口径。

## 3. 组件与数据

| 件 | 位置 | 说明 |
|---|---|---|
| `MallArea.tsx` | `apps/web/src/components/`（新） | 替换现 `ShoppingArea` 的挂载位（`/app/sim` 同一位置，不新增路由 = G3 沿用） |
| 商品卡 | MallArea 内子组件 | 图标用 astro-icon 同源的 Phosphor（按 dimension 映射），**不用真实品牌图、不 AI 生成商品图**（v1 省掉，避免"看起来像真货"）；年成本大字 + 来源链接 + 加购按钮 |
| 分类 tab | MallArea 内 | 全部 / 资产 / 消费品 / 体验，纯前端过滤（`option.kind` 现成） |
| 购物车抽屉 | MallArea 内 | `position: fixed` 右抽屉；`role="dialog"` + `aria-modal`；Esc 关闭、焦点圈定、背景 `aria-hidden` |
| 排序 | 年成本降序 | 贵的在前——视觉冲击就是教育 |

**复用清单**（一行不改）：`shoppingPool()`、`saveCartItem` / `readCart`、`cartAddedAnnualCost` /
`cartKindCounts` / `cartBurdenSummary`、`adoptCartAsGoal`、`poolOptionLabel`。
`ShoppingArea.tsx` 保留源码一个版本周期作回滚参照，冒烟迁完后删除。

## 4. 红线对照（逐条）

| 红线 | 落点 |
|---|---|
| 数值必须有来源 | 卡片金额只来自 `shoppingPool`（14 项全带 http(s) 来源），来源链接保留在卡上 |
| 不像真电商促销 | 无折扣、无倒计时、无"仅剩 X 件"、无真实品牌/商标图；图标为通用 Phosphor 示意 |
| 爽感必须被账单反驳 | 「结算」的唯一去向是账单日高亮；抽屉里负担率色块常显 |
| 两本账不混 | 仍只读写 `rich-sim:sim:v1` 的 `cart`；一键成目标走现有单向桥 |
| 无 JS 完整性 | Mall 是 client:load 岛，SSR 首帧为 null；卡 A 看板/账单/免责在 SSR 完整（沿用现纪律） |
| a11y | tab 用 `role="tablist"`；抽屉焦点管理；加购按钮 `aria-pressed`；44px 触摸目标；`motion-reduce` 关抽屉动画 |

## 5. 埋点

沿用 `sim:add` / `sim:remove` / `cart:to-goal`（事件名不变，worker 零改动）；
新增 `mall:checkout`（点结算，零 props）——事件名进 worker 正则白名单需同步（`[a-z]+:[a-z-]+` 现成覆盖）。

## 7. 验收

1. 未领起始金时 Mall 不出现（沿用 ClaimRunway 纪律）；领过才渲染。
2. 加购 → 抽屉计数与年成本同步；负担率色与账单日横幅同色同阈值。
3. 结算按钮滚动到账单日并高亮 1.5s；`mall:checkout` 入队。
4. SSR 源码无 Mall 岛；关 JS 页面其余部分完整。
5. 禁语扫描零命中（「优惠 / 折扣 / 抢购 / 仅剩」新增进 copy-guard 词表）。
6. 抽屉 Esc 可关、焦点不逃逸；390px 宽不溢出。
