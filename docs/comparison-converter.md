# 对比换算器（Comparison Converter）

> 状态：**v1 · 2026-10-05**。§2.1 轻量口径 + §3 四条边界**已实现**（M2 切片 S3：`packages/core/src/functions.ts` 的 `wealthTimeEquivalent` + `apps/web/src/lib/converter.ts`，设计器 sticky 与结果页两处挂载）；§2.2 本金口径未做。
> 目的：给 F5 之前的一段空窗提供一个**立刻能用现有数据制造好奇心**的机制，并顺带抬 F1→F2→F3 的完成率。
> 关联：`PRD.md` §5 核心价值主张 / §6.2 核心公式 / §6.3 领域规则 / §8 F5、`simulation-gameplay.md` §2.3 六通道（本条是其 MVP 候选 #2）、`technical-design.md` §4.2 币种口径。
> 数值纪律：富人侧金额**唯一事实源是 `packages/core/src/catalog-data.ts`**，本文不复制金额表，只引用。

---

## 1. 一句话

**把富人的年度账单，翻译成用户自己的时间单位。**

「私人飞机一年 $1,000,000」不产生好奇——量级超出经验，人脑只会跳过。
「私人飞机一年 = **你要存 100 年**」产生好奇——它把陌生量级钉回用户能感受的尺度，荒谬感来自这个换算而不是那个数字。

## 2. 两种口径，各自的任务

### 2.1 轻量口径（默认展示，用于冲击）

```
年数 = 富人项年成本(本位币) ÷ 用户年净储蓄
用户年净储蓄 = (月收入 − 月支出) × 12
```

- **纯除法，不含任何假设**：不用 `returnRate`、不用 `withdrawalRate`、不复利。
- 因此它**不是推演、不是预测**，是一句算术陈述——合规风险最小，不需要挂假设清单（见 §5）。
- 文案模板：`他这一年的「{item}」= 你按现在的存法要存 {n} 年`。

### 2.2 本金口径（可展开，用于教育）

```
本金 = enoughLine(年成本) = 年成本 ÷ withdrawalRate      // core 公开函数
年数 = 用 project(p, { kind:'enough-line', value: 本金 }, a) 反解
```

- **不要新写复利求解**：`yearsToTarget` 与 `MAX_YEARS` 在 `functions.ts` 里是**模块私有**（:22、:42），没进 barrel。要用只能走公开的 `project` / `gap`；确实不够用时，导出它们属于**改契约**，按 `CONVENTIONS.md` 要过闸门，不得私自改。
- 语义从「存够花一年」升级为「**养得住**」：拥有它的真门槛是那笔本金。
- **必须挂在假设清单之下展示**（`withdrawalRate` 默认 4%、`returnRate` 默认 4%，PRD §6.2 要求二者显式可调）。
- 默认折叠，标题写「想养住它，需要多少本金」。

## 3. 口径与边界（这四条是正确性要求，不是打磨项）

1. **币种**：catalog 是 USD/年，而分母（用户收入/支出）存的是**录入币种**（`profile.currency`，按契约恒等于展示本位币）。**分子必须换成与分母同币种后再相除**——直接拿 USD 除以本位币不是「结果相同、只是展示不一致」，而是**差一个汇率因子的错值**。现成的正确路径就是 `apps/web/src/lib/results.ts:80-84` 的 `annualCostLocal = convert(annualCostUSD, 'USD', profile.currency, assumptions.fx)`，**复用它，不要自创换算**。见 `technical-design.md` §4.2 与 `CONVENTIONS.md` 币种口径。
2. **分母 ≤ 0**（月支出 ≥ 收入）：`project` 已返回一等状态 `no-net-savings`。换算条此时**不得显示 ∞ / NaN / 负数**，改为一等文案：`按你填的数，目前每月没有净储蓄——这条先算不出年来`。
3. **年数超出人生尺度**：设上限 `MAX_YEARS = 60`（core 已有）。超过就**不给数字**，改为倍数表达：`他这一年的 {item} ≈ 你 {k} 年的全部结余`（k = 年成本 ÷ 年净储蓄，无上限），并在 k 也大到荒谬时（如 > 1000）收口成一句陈述而不是数字。给一个「17562 年」不会引发好奇，只会让人划走。
4. **汇率来源**：沿用现有 `/api/fx`（Frankfurter ECB），换算快照必须进 `Assumptions` 参与版本化，与 PRD §6.2「所有结果必须附带假设清单」一致。

## 4. 放在哪

| 位置 | 形态 | 作用 |
|---|---|---|
| **F1 设计器 sticky 条**（选到理想/富豪档时） | 轻量口径一行 | 用户**正在做选择**的那一刻给反差，是最强的好奇时刻；未录入财务时该行变成「先填 4 个数就能算出来」→ **直接抬 F2 完成率**，这是本条顺带的收益 |
| **F3 结果页** | 轻量口径一行 + 本金口径可展开 | 已有完整 Profile，两种口径都能算 |
| 首页 | **不做** | 没有用户数据，只能编一个假分母，违反 §6.3「所有输入均为用户自填」 |

## 5. 为什么不踩红线（逐条对 AGENTS.md / PRD）

- **不做投资建议、不荐股、不推荐产品**：换算条只换算「金额 ÷ 储蓄 = 年数」，不出现任何金融工具、不出现"该怎么配置"。
- **不预测**：文案禁用「你将会 / 你需要攒到」；只说「按你填的数，它等于」。
- **显式假设清单**：轻量口径无假设（纯除法）；本金口径的两个率必须显示在假设清单里并可调（PRD §6.2 硬要求）。
- **不做社交攀比**（PRD §3.2）：对照对象是**内容里的虚构/公开画像**，不是其他用户；无排行榜、无他人数据、无分享卡。
- **避开暴富信号**（PRD §13.1）：措辞纪律——主语永远是**它的代价**，不是**他的拥有**。反例：「你也能够拥有私人飞机」；正例：「私人飞机一年要付 100 万，不飞也付」。这条同时是它比炫富版更有好奇心的原因。

## 6. MVP 范围

**做**：轻量口径一行 + 三个边界状态（币种、分母 ≤0、超上限）+ 设计器 sticky 与结果页两处挂载 + 埋点事件 `converter:view` / `converter:expand`。
**不做**：本金口径的多年份曲线、任意两项富人的组合换算、与阶梯目标（F4）的联动、任何「怎么存」的建议。

实现现状（S3，2026-10-05）：上面「做」的部分除 `converter:expand` 外全部落地——`converter:expand` 属于 §2.2 本金口径的展开位，那一档未做，所以这个事件当前无从触发（不是埋了没上报）。

工作量估计：**S–M**。复用 `convert` / `enoughLine` / `yearsToTarget`，新增的是一个纯函数（建议 `wealthTimeEquivalent(annualCostUsd, profile, fx, baseCurrency)`）+ 两个展示位 + 测试。纯函数可单测，符合 `CONVENTIONS.md` 的口径冻结纪律。

## 7. 验收

1. 同一 profile 下，轻量口径结果 = 手算 `年成本(本位币) ÷ 年净储蓄`，误差为 0（纯除法，不做浮点安慰性四舍五入以外的加工）。
2. 月支出 ≥ 收入时不出现 `Infinity` / `NaN` / 负数，显示一等状态文案。
3. 切换展示币种时**年数必须不变**、显示的金额随币种变。这条性质有依据：`CurrencySwitcher.tsx:32-36` 会把 profile 各金额一并换算到新币种，所以分子分母同比例缩放——一旦年数随币种漂移，就是漏了分子换算。
4. 超过 60 年时不显示年数、显示倍数表达；k 极大时收口成陈述句。
5. 本金口径展开后，假设清单里能看到 `withdrawalRate` 与 `returnRate`。
6. 全站搜不到「你也能」「你将拥有」这类暴富句式。

## 8. 它不解决什么（诚实边界）

- 它**不是 F5**。F5 的最小版（身份剧本 + 资产看板 + 现金流波动 + 账单日）仍然要做，本条只是把「他 vs 我」这一条通道先跑起来。
- 它**不能被验证**，直到 `PUBLIC_CF_WEB_ANALYTICS_TOKEN` 配上——没有漏斗读数，「好奇心有没有被勾起」只是一句主张。所以本条的排期前提是度量，不是开发。
