> 状态：**v2 · 2026-10-05**。**§7 P1 已实现**（2026-10-05，M2 切片 S4）：领钱入口 + 两拍 + `sim-draft.ts` + A 生活线挂载。入口受 `PUBLIC_HOMEPAGE_CLAIM` 开关控制，**未配置时不出现**；**2026-10-05 晚已在 Pages Production 配 `=1` 并经新构建生效（Preview 未配）**，线上首页可见、冒烟 37/37。**P2 动效已做（2026-10-08，金币雨）**；分流页维持 §7.1 #3 取值不做；P3 投资线未做。
> 起因：发起人要求「访问即可领取 100 万美元、注明虚拟模拟起始金、之后可设计理想生活或走投资路线」。
> **v2 相对 v1 的实质变化**：v1 反对「把钱写进 `savings`」并改用「领一套一百万/年的生活」。**加上「虚拟起始金」标注 + 领后分流之后，这笔钱不再落在现实账本上，v1 那条反对对本设计不再成立**，故按两本账重写。v1 的红线对照、开关与埋点纪律保留。

## 1. 一句话

**开局发一百万，但这一百万在另一本账上——而且它不够。**

## 2. 为什么「不够」是这个设计的命门

实测（`packages/core/src/catalog-data.ts` + `defaults.ts` 的 `withdrawalRate 0.04`）：

| 事实 | 数字 |
|---|---|
| 默认理想生活年成本 → 够用线 | $101,600 → **$2,540,000** |
| $1M 按 4% 提取率，一年只能产出 | **$40,000** |
| 独栋豪宅一年的税 + 维护 | **$120,000** |
| 私人飞机年运营全口径 | **$1,000,000** |
| 全顶档生活一年（7 个维度全取最贵） | **$6,800,000** → $1M 只够 **约 7.6 周**（= 1.76 个月） |
| ~~全顶档 $7,025,000~~ | **已更正（2026-10-05）**：原文写 $7,025,000，目录实测 $6,800,000。差值来自 2026-10 的目录源头校准（`26b4f4b`），不是口径变化。写以上四行时以 `catalog-data.ts` 为准，不要沿用本文任何旧数。 |

两个结论：

1. **不能让它够。** 若起始金够用，`project` 算出来的年限直接塌到 0（`types.ts:128`：目标 ≤ 起始本金 → `years = 0`），用户领完就看到"你已达成"，爽感一秒耗尽、没有任何后续动机。$1M 相对默认生活是 **39% 到位**，相对顶档生活是 **7 周**——它必须停在"听着很多、其实不够"这个位置上，这才是渴望的来源。
2. **第二拍不是"原来这么贵"，是"原来我这么少"。** 揭示文案：`$1,000,000 按 4% 一年只能给你 $40,000 —— 连一套豪宅的年度税和维护都不够。`

## 3. 结构：两条账本 + 单向桥

```
首页 ──「领 $1,000,000 虚拟起始金」──▶ SIM 态（全程标注：虚拟模拟起始金 · 不是你的真实资产）
                                        ├─ A 生活线（= F5 最小版，已排 M2）
                                        │    用起始金撑一套理想生活 → 账单日 → 现金流
                                        └─ B 投资线（合规风险集中，建议押后）
                                             把起始金分配到资产类别 → 按用户自填假设推演
                                        │
                                        └──「换成我的真实生活」──▶ REAL 态
                                                     现有 F2 → F3 → F4，零改动

SIM ──▶ REAL：只允许单向、带标签的换算（comparison-converter：他一年 = 你 N 年）
REAL ──▶ SIM：禁止回填。真实数字不污染模拟，模拟数字不冒充现实。
```

### 3.1 存储必须物理分开（这条是硬约束，不是偏好）

`apps/web/src/lib/draft.ts` 顶部标注 **frozen**，`schemaVersion: 1`、`DRAFT_KEY = 'rich-sim:plan:v1'` 是冻结契约（`CONVENTIONS.md`：改契约 = 过闸门）。

所以模拟态**用独立 key `rich-sim:sim:v1`**，不加 `isExample` 字段、不 bump schema：

```ts
// 新增模块 apps/web/src/lib/sim-draft.ts，与 draft.ts 平级、互不引用
type SimState = {
  schemaVersion: 1;
  startingCapital: number;      // 1_000_000，固定或用户选档
  choices: LifeChoice;          // 复用 core 类型
  profile: Profile;             // 复用 core 类型：savings = startingCapital
  allocation?: Record<AssetClass, number>;  // B 线才用；AssetClass 在 core 里不存在，需本模块自定义
  currency: Currency;
  assumptions: Assumptions;     // 与 REAL 共用 DEFAULT_ASSUMPTIONS
  updatedAt: string;
};
```

> 上面的 `Profile` / `LifeChoice` / `Currency` / `Assumptions` 都是 `packages/core/src/types.ts` 的既有导出（实测 :8 / :23 / :40 / :71）；**只有 `AssetClass` 是新的**，且仅在 §7 P3 投资线才需要——**P1 不引入任何新类型**。

好处：**「两本账不混」由结构保证，不靠纪律**。`readDraft()` 永远读不到模拟数据，所以模拟值不可能被静默当成用户的现实。

### 3.2 零契约改动

`Profile = { income, expense, savings, debt }`，`project` 的起始本金 = `savings - debt`。所以模拟态直接喂 `{ savings: 1_000_000, ... }` 就能复用 **`project` / `gap` / `enoughLine` / `scenarioAnnualCost` / `buildMilestones` 全部五个函数**，`Goal` 现成支持 `{ kind: 'net-worth', value }`。**不新增引擎函数、不改任何口径。**（F2 2026-10-08 新增取数辅助 `profileMonthlyExpense`：SIM 态 `income = expense = 0`、无 `expenseBreakdown`，行为逐位不变，此结论仍成立）

### 3.3 三状态在这里第一次真正咬人

撑一套顶档生活时 `(income − expense) × 12` 必为负 → `project` 返回一等状态 **`no-net-savings`**。

> 你有 100 万，但你的生活方式让你连净储蓄都是负的。

这句是产品最强的教育时刻，而它是**现成状态**，不需要写任何新判定。

## 4. 交互时序

| 时刻 | 屏上 | 情绪 |
|---|---|---|
| T+0 | 按钮「**先领一百万**」（`<a>` 降级为普通链接，关 JS 仍可用） | 好奇 |
| T+0.3s | 金币/纸屑 + 大字「**$1,000,000 虚拟起始金已到账**」，下方常驻小字「虚拟模拟起始金 · 不是你的真实资产」 | 爽 |
| T+1.8s | 翻转：「按 4% 提取率，它一年只能给你 **$40,000**」+ 三行真实年成本对照（豪宅 $120,000 / 私人飞机 $1,000,000 / 全顶档 $7,025,000）+ 来源与口径 | 落差 → 渴望 |
| T+3s | 分流：「用它撑这种生活」（A）/「换成我的真实生活」（REAL）；B 线按钮在押后期不出现 | 转化 |

特效默认**静音**；系统开启 `prefers-reduced-motion` 时跳过 T+0.3s 直接呈现 T+1.8s 的账单态（PRD §9 WCAG AA）。

## 5. 红线对照（逐条，可核）

| 红线 | 本方案怎么守 |
|---|---|
| 输入必须用户自填（PRD §6.3） | 约束只作用于 **REAL** 态。SIM 态的 $1M 全程标注为虚拟起始金，且**永不写入 `DRAFT_KEY`**（§3.1 结构保证） |
| 不是爽游（PRD §5） | 爽感给 1.5 秒，随后必须被账单反驳。「已到账」若不在 2 秒内出现第二拍，本条即失效——这是可验收的，不是口号 |
| 避开暴富信号（PRD §13.1） | 主语永远是**它不够**，不是**你拥有了**。禁语：「你也能够」「你将拥有」「稳赚」「躺赚」「预期收益」 |
| **不荐股 / 不推荐具体金融产品**（B 线命门） | 只出现**资产类别**（现金/债券/股票/房产/另类），永不出现标的、基金名、代码；**不做"推荐配置"按钮**（那才是投资建议） |
| 不预测、不承诺结果 | 收益率必须是**用户自填的显式假设**并常驻假设清单；文案是「你假设它每年 4%」，不是「它每年会 4%」 |
| 显式假设清单 + 免责声明 | SIM 与 REAL 共用 `AssumptionsPanel`，SIM 态额外多一行「起始金为虚拟 · 结果为模拟推演」 |
| 不做社交攀比（PRD §3.2） | 无排行、无他人数据、无分享卡、无"超过 X% 的人" |
| 冻结契约（`CONVENTIONS.md`） | 不改 `types.ts` / `draft.ts` schema / 五个引擎函数口径；只新增 `sim-draft.ts`、一个首页岛、SIM 渲染分支 |

## 6. 开关与度量

- **开关**：`PUBLIC_HOMEPAGE_CLAIM=1`（构建期环境变量，沿用 `Analytics.astro:14-16` 的读法）。未配置时首页与现在**逐字节相同**。
- **事件**（现成 `track(event, props)`，`analytics.ts:64`）：`claim:tap` → `claim:reveal` → `claim:bill` → `route:life` / `route:real` /（后期）`route:invest`；SIM 内复用现有 `designer:select` / `results:view` / `currency:switch`。
- **成功判据**：`claim:tap → route:real → F2 完成` 的转化，对比现首页「开始设计理想生活」的同一路径。
- **诚实前置**：`PUBLIC_CF_WEB_ANALYTICS_TOKEN` 未配 → 以上事件**一个都收不到**。本条排期前提是度量，不是开发。
- **上线状态（2026-10-05）**：代码已合进 main，但 **Cloudflare Pages 项目没有配 `PUBLIC_HOMEPAGE_CLAIM`，所以线上入口不出现**。要不要开、开多久，是发起人的决定——开了之后每次首页访问都会看见它，这是不可逆的用户体验改动（可以用同一开关回滚）。

### 7.1 P1 落地取值（2026-10-05，§9 未拍板项的临时选择）

未拍板项不可能停下整条流水线，所以 P1 按下面三条实现。**每条都可翻**，翻的条件写在同一行，拍板后回写本节即可：

| §9 项 | P1 取值 | 为什么这样取 | 翻转条件 |
|---|---|---|---|
| #1 起始金档位 | ~~固定 $1M~~ **2026-10-08 拍板：三档 $100K / $1M / $10M**（`SIM_CAPITAL_TIERS` + `capitalFromParam`，默认仍 $1M） | 教育性优先：同一份生活对三档起始金是三种命运，「差一个数量级」本身就是一课；入口按 idle 态三按钮实现，未增加屏幕数 | 已拍板；若 `claim:tap` 转化读数显示三档入口分流严重可收回固定 $1M |
| #2 SIM 态要不要 income | **不要**（`income = expense = 0`，只有 `savings = startingCapital`） | 任何非零 income 都是编出来的数，本仓库不编数据 | 一旦确立收入的来源口径（明示虚构并从某个已公开的比率推导），才可能启用 `project` |
| #3 是否先给路线选择页 | **不选择，直接在首页面板内分流**（A 线 / REAL 两个按钮） | 落点在 S1 的 `/app/sim` 与既有 `/app/finance`，多一屏等于多一次流失而没有新增信息 | 投资线（P3）真要做时才需要一个正经的分流页 |

由此产生的两条**后果**，都写进测试而不是留在口头：

1. **P1 的 SIM 态不用 `project`**：没有收入 ⇒ `project` 一律返回 `no-net-savings`，此时算出的年限是假的。"够撑多久"因此走纯除法（本金 ÷ 年成本），与 §2 自己的口径一致（`runwayMonths`）。**§8 验收 #8 在 P1 不适用**——它防的是「领完就看见 `years = 0` 的已达成」，而纯除法路径根本不调 `project`；等 SIM 长出真正带收入的推演面时，这条自动恢复。
2. ~~**§4 的金币/纸屑动效未做**~~ ✅ **2026-10-08 P2 已做**：granted 拍的金币雨（18 枚、确定性落点、纯 CSS keyframes、静音、无依赖），reduced-motion 双保险（组件不到 granted + CSS 兜底 `display:none`），冒烟新增「第一拍有金币雨」断言。分流页维持 #3 临时取值（不做，等 P3 投资线）；SIM↔REAL 桥已由 M3 S5「一键成目标」覆盖。

## 8. 验收

1. 访问任一 SIM 路由后 `localStorage.getItem('rich-sim:plan:v1')` 仍为 `null`（两本账不混的**结构性**断言）。
2. 未设 `PUBLIC_HOMEPAGE_CLAIM` 时首页 HTML 与改动前逐字节一致（构建产物 diff）。
3. 第二拍在 2 秒内出现，且包含来源 URL 与「年运营全口径」字样。
4. 禁语清单全站扫描零命中：「你也能」「你将拥有」「稳赚」「躺赚」「预期收益」。
5. B 线（若做）：界面上不存在任何具体标的名与"推荐配置"控件，加一条源文本断言钉住。
6. `prefers-reduced-motion` 开启时无特效直接到账单态；关 JS 时首页按钮仍是可用链接。
7. SIM 结果页假设清单里能看到「起始金为虚拟 · 结果为模拟推演」。
8. 用 $1M 起始金 + 默认生活跑 `project`，返回的不是 `years = 0`（若为 0，说明起始金档位定得太高，见 §2 结论 1）。

## 9. 未决（要拍板才动）

1. **起始金固定 $1M，还是给 $100K / $1M / $10M 三档**——三档把"不够"变成可对比梯度，教育性更强但入口变复杂。
2. **SIM 态要不要 income**：纯吃本金（`income = expense`）最直白地展示"坐吃山空"，但会让 `no-net-savings` 恒成立、失去"边赚边花"的张力。
3. 领完默认直接落 A 生活线，还是先给路线选择页。
4. **B 投资线到底做不做**（§7 P3）。
5. 海外市场的 SIM 文案与币种口径（挂 `deferred-items.md` #1）。
