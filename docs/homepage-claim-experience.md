# 首页「领一百万」+ 示例 Profile 方案

> 状态：**方案草案 v1 · 2026-10-05**，未拍板、未排期、未写代码。
> 起因：发起人提出「首页放一个领钱按钮 + 爽感特效，金额 100 万美元作为初始资金」。本方案**保留这个钩子的全部心理强度**，但改掉会拆产品的那一半。
> 关联：`PRD.md` §4.2 Persona / §5 核心价值主张 / §6.3 领域规则 / §13.1；`simulation-gameplay.md` §1；`CONVENTIONS.md` 冻结契约；`comparison-converter.md`（同一批好奇心机制）。

---

## 1. 为什么不能真的发一百万进 `savings`

`defaults.ts` 现在只有假设默认（`returnRate 0.04` / `withdrawalRate 0.04` / `inflation 0.03`）和币种默认，**没有任何 profile 默认值**。把 100 万塞进 `savings` 之后，够用线、差距、年限全部由一个不是用户的数字驱动，而输出长得跟真结果一模一样。

违反三条，且都是产品自己的差异化所在：

- **PRD §6.3**「所有输入均为用户自填，系统不引入任何外部『建议』」；
- **PRD §5**「不是爽游，也不是记账本」——发初始资金 + 彩带就是爽游的标准配置；
- **PRD §13.1** 明确要求避开「幻想财富」这类暴富信号。

真正的风险不是"给了假钱"，是**假输入产出看起来全真的输出**。

## 2. 改一行就成立的版本：领的不是钱，是「一百万/年的生活」

按钮文案照旧有冲击力，爽感照给，但**账单在 1.5 秒后落下**：

| 时刻 | 屏上 | 情绪 |
|---|---|---|
| T+0 | 按钮「**先领一百万**」 | 好奇 |
| T+0.3s | 金币/纸屑特效 + 大字「**$1,000,000 已到账**」 | 爽 |
| T+1.8s | 同一屏翻转：「这是**私人飞机一年的运营费**。不飞也付。」+ 该项来源与口径 | 落差 → 好奇（真） |
| T+3s | 两个出口：「看它要多少本金」/「换成我的生活」 | 转化 |

数字全部来自事实源，不新造：`packages/core/src/catalog-data.ts` 实测 `private-jet` 年运营全口径 **$1,000,000**、`superyacht` 档 **$5,400,000**、全顶档合计 **$7,025,000**（→ 够用线 `÷4%` = **$175,625,000**）。

> **口径提醒**：`catalog-data.ts:14` 明确「富豪极端档无政府统计，采用行业公开估算」（例：50 米游艇年运营 400–600 万 EUR 取中值换算）。所以特效引用的必须是**区间中值 + 来源 URL**，文案不得写成"官方统计"；这条与 §4 的「不预测、不承诺」是同一类纪律。

这正是 `simulation-gameplay.md` §1 那句话的界面化：「价格标签是假的爽，持有成本是真的痛」。**爽感没有被删掉，是被设计成两段**——第二段才是别人抄不走的东西。

## 3. 示例 Profile：来源、币种、以及一条结构性约束

### 3.1 数值不新造

示例 profile 直接取 **PRD §4.2 Persona A**（文档内既有产物，非本次编造）：26 岁一线城市互联网从业者，**月薪 2 万、存款 8 万、无房、无负债**，`profile.currency = 'CNY'`，展示时由现有 `convert` 换算到本位币。

> **缺口 ①（`待定`，不许我填）**：Persona A 只给了月收入与存款，**没有给月支出**。而 `project` 的分母正是 `(income - expense) × 12`——没有支出就算不出年限。必须补一个**有来源的**支出锚点（例如 BLS CE / 统计局居民人均消费支出对应分位），不能随手写一个数凑过验收。
>
> **缺口 ②（`待定`）**：第一阶段目标市场是海外（`technical-design.md` §9），需要一个**有来源的海外 persona**，而不是把中国 persona 硬换算给美国用户。挂到 deferred #1（多币种/口径）一起解决，**上线海外版前必须补**。

### 3.2 示例**绝不进 draft**——用路由态，不用字段

`apps/web/src/lib/draft.ts` 顶部写着 **frozen**，`schemaVersion: 1` 是冻结契约（`CONVENTIONS.md`：改契约 = 过闸门）。所以**不加 `isExample` 字段**，改成：

- 特效结束后跳 `/app/result?example=persona-a`；
- 结果页识别该参数时，**在内存里现造 profile 渲染，完全不读写 `DRAFT_KEY`**；
- 顶部常驻徽标「**这是示例数字 · 换成你的**」（复用 `ResultsView.tsx:173`「示例路径，非承诺」的同一视觉语言），点击 → `/app/finance` 填真数；
- 假设清单里多一行「输入来源：示例（Persona A）」。

好处：**「不污染用户数据」由结构保证，而不是靠纪律**。`readDraft()` 拿不到东西，就不可能被静默覆盖。

## 4. 红线对照（逐条，可核）

| 红线 | 本方案怎么守 |
|---|---|
| 不做投资建议 / 不荐股 / 不推荐金融产品 | 特效与文案只出现**生活项目与其持有成本**，不出现任何金融工具、收益率承诺、"该怎么配置" |
| 不预测、不承诺结果 | 禁语清单：「你也能」「你将拥有」「只需 X 年就能」。示例态一律用「按这组示例数字，算出来是」 |
| 显式假设清单 + 免责声明 | 示例结果页与真实结果页共用 `AssumptionsPanel`，额外多一行输入来源 |
| 不做社交攀比（§3.2） | 无排行、无他人数据、无分享卡、无"你超过了 X% 的人" |
| 避开暴富信号（§13.1） | 主语永远是**代价**不是**拥有**；「已到账」必须在 2 秒内被账单反驳，否则就是纯爽游 |
| 输入必须用户自填（§6.3） | 示例走路由态、不落 draft；用户自己的数字仍然只来自 F2 |
| 冻结契约（CONVENTIONS.md） | 不改 `types.ts` / `draft.ts` schema / 五个引擎函数口径；只新增一个纯展示用的 persona 常量与一个页面分支 |

## 5. 开关与度量

- **开关**：`PUBLIC_HOMEPAGE_CLAIM=1`（构建期环境变量，沿用 `Analytics.astro:14-16` 的读法）。未配置时首页与现在**逐字节相同**，零风险回退。
- **事件**（现成 `track(event, props)`，`analytics.ts:64`）：`claim:tap` → `claim:reveal`（特效起）→ `claim:bill`（账单落）→ `claim:exit-example` / `claim:exit-real`（两个出口）。
- **成功判据**：`claim:tap → /app/finance 完成` 的转化，对比现有首页 `开始设计理想生活` 按钮的同一条路径。
- **诚实前置**：`PUBLIC_CF_WEB_ANALYTICS_TOKEN` 未配 → 上面四个事件**一个都收不到**。所以本条的排期前提不是开发，是度量接通。

## 6. 范围

**做**：首页按钮 + 两态特效 + `?example=persona-a` 结果态 + 徽标与出口 + 开关与四个事件。
**不做**：任何写入 `savings` 的初始资金；账户/余额概念；连续签到或"每天领"；分享卡；音效默认开（默认静音，可点开——移动端公共场合）。

工作量估计 **M**：特效与 `?example=` 分支是新代码，其余全是复用。

## 7. 验收

1. `grep -rn "savings" apps/web/src/pages/index.astro` 与新增文件中**不得出现把金额写入 profile 的路径**；单测断言：访问 `?example=persona-a` 后 `localStorage.getItem('rich-sim:plan:v1')` 仍为 `null`。
2. 特效第二态在 2 秒内出现，且包含该项的 `source` 链接与「年运营全口径」字样。
3. 未设 `PUBLIC_HOMEPAGE_CLAIM` 时，首页 HTML 与改动前**逐字节一致**（构建产物 diff）。
4. 禁语清单全站扫描通过：「你也能」「你将拥有」「稳赚」「躺赚」零命中。
5. 示例结果页的假设清单里能看到「输入来源：示例（Persona A）」。
6. 关掉 JS 时首页仍然可用（按钮退化为普通链接进设计器）——与测算输出「服务端渲染，不被 JS 关掉」同口径（PRD §8 F3 / `handoff.md` T09）。
7. 特效遵守 `prefers-reduced-motion`：系统开启减少动效时，直接呈现第二态账单、不放金币（PRD §9 可访问性 WCAG AA）。
